## 系统提示词——最重要（2:00-4:00）

**[画面]**：展示 system prompt 核心部分

```python
DEFAULT_SYSTEM_PROMPT = """你是智能家居管家，运行在用户的 Home Assistant 系统中。

## 核心能力
1. 🏠 智能家居控制
2. 💬 通用对话推理
3. 🧠 上下文感知

## 场景理解
- "睡觉了" → 关灯、空调睡眠模式
- "出门了" → 关所有设备
- "看电影" → 调暗灯光、关窗帘

## 回复风格
- 操作后简短告知结果
- 失败时说明原因
"""
```

**[旁白]**：这是整个系统最关键的部分。提示词很简单，就一件事——让 Claude 在场景列表里找匹配。

三个要点：
1. **只匹配场景**——用户说什么都在场景列表里找，找到就触发
2. **不干多余的事**——不要自己控制设备，不要拆指令
3. **保留通用能力**——查天气、算数、翻译这些能正常回答

**[tips]**：如果你发现 Claude 不按你的想法来，90% 是提示词没写好。可以对照本项目的 `claude_system_prompt.md` 调。

## 设备上下文注入（4:00-6:00）

**[画面]**：展示 _build_device_context() 方法

```python
async def _build_device_context(self) -> str:
    """获取 HA 中所有设备的状态"""
    states = self.hass.states.async_all()
    
    # 按区域分组
    for state in states:
        if state.domain in ("automation", "script", ...):
            continue  # 跳过系统实体
        line = f"  • {state.entity_id}: {state.state}"
        if state.attributes.get("brightness"):
            line += f" [亮度={state.attributes['brightness']}]"
```

**[旁白]**：每次 Claude 收到你的指令之前，我们先把家里所有设备的状态整理成文本发给它。

**[画面]**：实际发出去的文本长这样
```
【可用场景（Scene）】
  • 睡眠模式 (scene.sleep_mode)
  • 离家模式 (scene.leave_home)
  • 回家模式 (scene.arrive_home)
  • 观影模式 (scene.movie_mode)

【设备状态】
  [客厅] light.living_room_ceiling: on [亮度=255]
  [客厅] climate.living_room_ac: cooling [温度=26度]
  [客厅] cover.living_room_curtain: closed
  [卧室] light.bedroom_lamp: off
  [卧室] climate.bedroom_ac: idle [温度=28度]
```

**[旁白]**：注意——场景列表放在最前面。Claude 会先看有没有匹配的场景，有就触发场景，没有才去控制单个设备。你说"睡觉"，它看到有 scene.sleep_mode，就直接触发了，不会自己去猜应该关哪几个灯。

**[画面]**：展示工具定义

```python
HA_SERVICE_TOOL = {
    "name": "execute_ha_service",
    "description": "执行 Home Assistant 服务来控制设备",
    "input_schema": {
        "type": "object",
        "properties": {
            "domain": {"type": "string", "description": "设备域: light, climate..."},
            "service": {"type": "string", "description": "服务: turn_on, set_temperature..."},
            "entity_id": {"type": "string", "description": "实体ID"},
            "area": {"type": "string", "description": "区域名"},
            "data": {"type": "object", "description": "额外参数"},
        }
    }
}
```

**[旁白]**：这是 Claude 的 Tool Calling 功能——我定义了一个工具"执行 HA 服务"，Claude 可以自主决定要不要调用。

**[画面]**：展示场景触发过程
```
用户说："准备睡觉了"
Claude 思考：可用场景列表中有 scene.sleep_mode → 匹配
Claude 调用：execute_ha_service({
    domain: "scene",
    service: "turn_on", 
    entity_id: "scene.sleep_mode"
})
→ 你在米家里配的睡眠场景被执行
```

**[旁白]**：关键区别——Claude 不是自己拆解"睡觉要做开灯还是关灯"，而是直接触发你已经在米家里配好的场景。场景内容由你决定，Claude 只负责"听懂 → 匹配 → 触发"。

**[画面]**：单个设备控制的调用
```
用户说："太热了"
Claude 思考：当前温度28度 -> 调低空调（没有场景匹配，直接控制）
Claude 调用：execute_ha_service({
    domain: "climate",
    service: "set_temperature", 
    area: "客厅",
    data: {temperature: 26}
})
```

## 执行设备操作（8:00-9:30）

**[画面]**：展示 _execute_ha_service() 方法

```python
async def _execute_ha_service(self, tool_call):
    params = tool_call["input"]
    
    # 如果指定了区域，自动找该区域下的设备
    if area_name:
        entities = await self._find_entities_by_area(area_name, domain)
    
    # 调用 HA 服务
    await self.hass.services.async_call(
        domain=domain,
        service=service,
        service_data=data,
        blocking=True,
    )
```

**[旁白]**：简单说就是——Claude 决定操作，Python 执行。Claude 说"调客厅空调到 26 度"，代码就去调 HA 的 climate 服务。

**[画面]**：特别展示按区域查找的逻辑

```python
async def _find_entities_by_area(self, area_name, domain):
    """根据区域名称查找设备"""
    for entry in entity_registry.entities.values():
        if entry.area_id == target_area.area_id:
            if domain and entry.entity_id.startswith(domain):
                entities.append(entry.entity_id)
```

**[旁白]**：Claude 说"关灯"，但你没说哪个房间的灯。通过区域映射，它能关掉正确房间的灯。

## 为什么选自定义组件？（9:30-11:00）

**[画面]**：对比表

```
HA 内置 OpenAI 集成 vs 自定义 Claude 组件：

HA 内置：
✅ 不用写代码，配置就行
❌ 只能文本回复，不能调用设备
❌ 看不到场景列表和设备状态
❌ 不支持工具调用（Tool Calling）

自定义组件：
✅ 能看到场景列表 → Claude 知道"睡眠模式"存在
✅ 能看到设备状态 → Claude 知道家里有什么
✅ 支持工具调用 → 能触发 scene.turn_on
✅ 完全可控 → 改提示词即可调教
```

**[旁白]**：这也是为什么我选择写自定义组件而不是直接用 HA 自带的 OpenAI 集成。如果没有工具调用，Claude 只能说"我建议你打开睡眠模式"——但打不开。而我们的组件能让它真的去触发场景。
